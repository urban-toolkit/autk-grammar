# Browser tests

These tests run gallery example specs through the grammar in Chrome with WebGPU, and check the results: loaded tables, spatial joins, GPU compute values, linked plots, and that each map canvas was actually drawn. They run the adapter and grammar **source** against whichever Autark packages are installed.

A map draws on demand, and Chrome can read an idle WebGPU canvas back as transparent, so a test reads a map canvas in the animation frame that draws the map: `window.readMap` asks the map for one frame (`requestRender()`) and reads the canvas in an animation frame callback registered after the map's own. `requestRender()` does nothing for a map whose `draw()` never ran, so such a map reads back blank.

CI (`.github/workflows/e2e.yml`) runs them on every pull request and every push to `main`, twice:

- **locked**: the Autark versions in `package-lock.json`.
- **latest**: the newest `@urban-toolkit/autk-*` releases on npm. A failure here while `locked` passes means a new Autark release broke the grammar.

## Running locally

```sh
npm install
npm run test:e2e
```

The tests need a Chrome with WebGPU. They use the system Chrome when it is installed; otherwise point `CHROME_PATH` at a Chrome binary.

## DuckDB's extensions

The DuckDB that autk-db runs in the page fetches its extensions from extensions.duckdb.org each time a database loads one: `spatial` as autk-db's `init()` starts, `json` the first time a query reads JSON. No test depends on that host. `tests/duckdb-extensions.ts` answers the page's requests to it from a copy in `tests/.duckdb-extensions` (not committed), laid out as the host's paths, and a request the copy cannot answer fails the test, naming the URL.

- **Filling the copy:** Playwright's global setup fetches what the copy lacks before the first test, for the DuckDB build in the installed autk-db (`npx tsx tests/duckdb-extensions.ts fetch` does the same by hand). The E2E workflow keeps the copy in the Actions cache under that build's version, and fetches it, with retries, in a step of its own only when the cache holds none.
- **A new extension:** when DuckDB asks for one the copy lacks, add its name to `EXTENSIONS` in `tests/duckdb-extensions.ts`; the cache key names the list, so the next run fetches it.

## Adding a test

`tests/app/main.ts` exposes `window.runExample(name)`, which runs `gallery/src/examples/<name>.ts` and returns the tables it produced, `window.runSpec(spec)`, which does the same for a spec the test builds and destroys the previous run's grammar first, `window.runAgain(spec)`, which runs a spec on the last run's grammar, as a host that keeps one does, `window.runInPanes(spec, width, height, styles?)`, which runs a spec in the panes the gallery hub builds for a spec with a layout (`gallery/src/views.ts`), with the hub's stylesheet when `styles` is `'hub'`, and returns each pane's box, `window.exampleSpec(name)`, which returns an example's spec so a test can run it changed (the test process cannot import an example that names a grammar enum, since it never builds the grammar), `window.valueAt(table, index, path)` to read a feature property, `window.featureExtents(table)` for each feature's extent in workspace coordinates (World Mercator meters), and `window.readMap(canvasId)`, which returns a map canvas as a PNG data URL. `window.dbRows(query)` gives the rows a SELECT finds in the last run's autk-db, counts as numbers, and `window.dbLayer(table, osmElements?)` a table as autk-db exports it: both read autk-db's own tables, apart from the grammar's caches, which maps, plots and `grammar.data` read first. `window.mapLayers(canvasId)` returns what autk-map holds for each layer of a map (id, colors, outline, line width and widths by feature, point size, color map, highlighted and hidden ids), `window.drawnRows(canvasId, layerId)` the properties of the feature a vector layer draws at each of its positions, read from the collection autk-map was handed, `window.rasterCells(canvasId, layerId)` a raster layer's cell values and colors, `window.handedBand(canvasId, layerId, band)` the values of a band of the raster autk-map was handed for a layer, `window.terrain(canvasId)` a map's terrain (the band autk-map was handed for it, that band's range, and the heightfield autk-map built from it), `window.buildingTops(canvasId, layerId)` the top of each building a buildings layer draws, or null for one it draws none of, `window.mapUi(canvasId)` which of autk-map's menu, legend and credit a map put next to its canvas, and `window.legend()` the legend's title and labels; `window.cameraView(canvasId)` gives where a map's camera is (its eye, the point it looks at, its line of sight and its up direction) with the map's origin, `window.turnCamera(canvasId, camera)` turns it with the grammar's `applyCamera`, as a host does, and `window.playTour(canvasId, motion)` plays a camera tour on it with `playCameraMotion`, keeping the tour in `window.tour` and setting `window.tourEnded` once it ends. A test that reads a tour at chosen times installs Playwright's clock (`page.clock`) before the run, so the clock draws each animation frame when the test says; `window.schemeColor(value, interpolator, domain)` and `window.domainLabels(domain)` give autk-core's color and labels to compare them with. For plots, `window.plotMarks(target)` returns the marks the plots in an element draw, each with the row autk-plot binds to it and its computed fill and stroke, `window.plotTicks(target, selector)` the tick labels of the axes a selector finds there (`#axisX`, `#axisY`, or parallel coordinates' `.autkBrush`), each as the tick's value and its text, `window.plotAxisTitles(target)` the axis titles, and `window.plotStyle()` the mark and highlight colors autk-plot holds for the page; `window.runBeside(spec)` runs a spec on a second grammar of the page, `window.besideGrammar`, whose plots draw in `#beside`, as a page that shows two specs does. Add a case to `tests/grammar.spec.ts` that runs an example and checks what it should produce; `expectDrawn(page, canvasId)` checks that a map drew, and `drawnPixels(page, name, canvasId)` counts the pixels a map drew apart from its background, for a scene of a few plain features.
